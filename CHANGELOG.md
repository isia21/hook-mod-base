# Журнал изменений

## v2.1

В этой версии добавлены подмена адресов в `PUSH`, проверка NOP-диапазонов и отладочная ловушка при входе в затёртый код. Карта памяти также показывает промежутки между NOP-диапазонами, которые стоит проверить в дизассемблере.

### Подмена адреса в `PUSH imm32`

В x86 адрес функции может передаваться как аргумент через `push offset`. Такой адрес хранится в 32-битном операнде инструкции. Теперь `HookType::Push` позволяет заменить его через тот же `InstallHook`, что используется для обычных точек перехвата.

```cpp
// nPushAddress указывает на опкод 0x68 в собственном x86-стенде.
m_tracker.InstallHook(
	nPushAddress,
	HookType::push,
	reinterpret_cast<uintptr_t>(&ReplacementCallback),
	"TargetApp::RegisterCallback"
);
```

Трекер проверяет опкод, сохраняет исходные пять байт для `RestoreAll()` и записывает четырёхбайтовый операнд. Независимость размера записи от `sizeof(uintptr_t)` предотвращает выход за пределы пятибайтового буфера. На x64 установка `Push` отклоняется до записи. В HTML и JSON этот тип отображается как `push`.

Для списков целей доступны строчные алиасы. `call` соответствует `Call`, `jmp` — `Jmp`, `dd` и `vtable` — `VTable`, `push` — `Push`. Числовые значения типов сохранились.

### Проверка границ NOP-диапазона

`HijackedFunction` принимает полуоткрытый диапазон `[start, end)`. В v2.0 при `end <= start` второй аргумент трактовался как размер. Опечатка в адресе могла поэтому привести к записи за пределами функции.

```cpp
HijackedFunction stRange(nStartAddress, nEndAddress, "TargetApp::OldUpdate");
// Если известна только длина, проверь переполнение перед вычислением nStartAddress + nSize.
```

Передавай конечный адрес, если старый вызов передавал размер вторым аргументом. Равные и обратные границы приводят к срабатыванию `assert` в Debug и к `std::invalid_argument` при отключённом `assert`. Трекер также проверяет согласованность границ и размера всей группы перед первой записью.

### Ловушка при входе в NOP-диапазон

Режим `NopMode::BreakOnEntry` помогает найти оставшийся вызов старой функции. При входе в начало затёртого диапазона `NopError()` показывает сообщение и вызывает `__debugbreak()`, чтобы в отладчике можно было посмотреть стек.

```cpp
m_tracker.InstallHook(
	nCallSiteAddress,
	HookType::call,
	reinterpret_cast<uintptr_t>(&ReplacementUpdate),
	"TargetApp::Update",
	{{nOldStartAddress, nOldEndAddress, "TargetApp::OldUpdate"}},
	NopMode::BreakOnEntry
);
```

Вызов обработчика занимает пять байт. Короткие диапазоны целиком заполняются NOP. Ловушка срабатывает при входе через начало диапазона. По умолчанию действует `NopMode::Fill` с обычным заполнением NOP.

### Промежутки на карте памяти

HTML-карта и JSON показывают диагностические пометки для зазоров между соседними NOP-диапазонами в одной исполняемой секции. Пересекающиеся диапазоны обрабатываются совместно, а другие занятые области учитываются при поиске зазоров.

| Пометка | Условие | Зачем нужна |
| --- | --- | --- |
| `Possible alignment (0xCC)` | Весь зазор состоит из `0xCC` | Помогает найти вероятное межфункциональное выравнивание для сверки с дизассемблером. |
| `Short gap` | Длина зазора строго меньше порога | Помогает заметить короткий непропатченный участок. |

Если выполняются оба условия, HTML показывает это в подписи, а JSON выдаёт `kind: "alignment"` и `short_gap: true`. Длина зазора сама по себе ничего не говорит о наличии исполняемого кода. Диагностика не переписывает байты, не увеличивает счётчик изменённых байтов и не добавляет патчи в скрипты IDA.

```cpp
manager.InitAll();    // Порог по умолчанию — 16 байт.
manager.InitAll(8);   // Другой вариант запуска с порогом 8 байт.
manager.InitAll(0);   // Только пометки о возможном выравнивании.
```

Выбери один вызов `InitAll` на цикл инициализации.

### Исправления сборки и отката

- Добавлена поддержка `Call`, `Jmp` и `VTable` на Windows x64. Дальность `rel32` проверяется до записи. Слоты VTable сохраняются, заменяются и восстанавливаются целиком (8 байт на x64 и 4 байта на x86).
- Для x64 добавлен запуск проверки через заново собранный `TargetApp.exe`. Он проверяет вызовы до установки, после установки и после отката, а также отказ при слишком далёком адресе.
- Чтение цели относительного перехода использует знаковое смещение `rel32` фиксированной ширины. Это исправляет ошибку сборки x64 и учитывает отрицательные смещения.
- Запись кода проверяет смену защиты страниц и обновляет кеш инструкций после изменения байтов.
- `NOPMemory` восстанавливает защиту страниц по исходному адресу диапазона. Раньше при восстановлении использовался указатель, уже сдвинутый за записанные байты.
- Профиль Windows, MSVC и C++20, а также ограничение фиксированных RVA в `TestAppHook` описаны в [README.md](README.md). Комплектный `examples/TargetApp.exe` соответствует этим адресам. Для другой сборки стенда адреса нужно сверить.
